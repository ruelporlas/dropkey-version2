CONFIRMED PRODUCT SCOPE
- Product management and association with plugin ZIP files.
- DropKey-managed checkout and purchase records.
- PayPal and Stripe for MVP, with future gateway extensibility.
- Protected download links expiring after 48 hours.
- Customer email with download link and license key.
- License key generation and administration.

- Product → Tier → Billing Options model, including free, one-time, monthly, and yearly options as applicable.

- WordPress action hooks for future extension.
- Clear admin UI with contextual help, validation, and next-step guidance.

USER-CONFIRMED MVP POLICIES RECORDED
- WordPress 6.4+ / PHP 7.4+ baseline; guest and account checkout; exact-URL activation identity.
- Editable example tiers Basic (1), Plus (3), Pro (10); customer and admin activation deactivation; admin-managed subscription cancellation at the end of the paid period; 3-day failed-payment grace period.
- Provider-state-based refund/chargeback baseline with separate chargeback policy; versioned ZIP releases and update API in MVP; private ZIP storage on host.
- Reissuable 48-hour download links with 5 downloads per link; taxes/coupons/invoices/trials deferred; email retry and admin resend.
- Full customer account pages and specified customer self-service actions; hosted provider payment flows, provider references/status only, no card storage.
- Milestone-based secure MVP approach.

IMPLEMENTED IN SOURCE (CODE EXISTS; RUNTIME BEHAVIOR NOT YET VERIFIED)
- WordPress plugin entry point and bootstrap using namespace DropKey\\V2 and text domain dropkey-v2.
- Database installer using dbDelta(), with separate schema version tracking.
- Schema version 6 defines prefixed tables for products, tiers, billing options, releases, licenses, activations, download tokens, orders, subscriptions, payment events, email queue, and payment history.
- Basic repositories with create/get/list/update/delete operations, field validation, and parent-child deletion guards.
- GitHub Actions PHP syntax workflow for PHP 7.4, 8.0, and 8.3.

IMPLEMENTED IN MILESTONES 2–4 (SOURCE EXISTS; WORDPRESS BEHAVIOR NOT YET VERIFIED)
- DropKey admin menu with product create/edit/status, tier create/edit and configurable activation limits, billing-option create/edit, versioned ZIP release upload, manual license issuance/status controls, active-site activation listing/deactivation, and protected download-link generation.
- Schema version 3 adds releases, licenses, activations, and download-token tables through dbDelta().
- ZIP upload validation and private storage path guard; files are stored outside the detected document root when that server variable is available, with additional .htaccess/index.php safeguards.
- License key hashing, license status/expiry validation, exact-site activation identity with trailing slash normalization, and per-tier active activation limit enforcement.
- Hashed 48-hour download tokens with up to 5 successful downloads per link and SHA-256 package integrity checking.
- Versioned REST endpoints for activate, deactivate, validate, update checks, and protected ZIP delivery; reusable PHP client at sdk/dropkey-license-client.php.


- Admin UI has scoped styling, responsive dashboard metrics and shortcuts, payment settings, order/subscription views, and failed-email retry controls.
- Public storefront shortcode `[dropkey_store]` lists published products/tiers/billing options and starts hosted checkout. Checkout is rate-limited per client IP/email; a published ZIP release is required before checkout.
- Stripe hosted Checkout supports one-time and recurring options, signed/timestamped webhook verification, provider-reference matching, subscription period lookup, and cancellation at period end.
- PayPal supports hosted one-time order approval/server-side capture, recurring plans referenced by PayPal Plan ID, provider-side webhook signature verification, refund/dispute matching, and deferred cancellation at period end.
- Orders, subscriptions, payment events, payment references, and encrypted email queue are stored separately. Webhook event IDs are unique; payment amount/currency are checked before fulfillment; email content is authenticated-encrypted at rest and retries are bounded.
- Free checkout issues a license through the same transactional fulfillment path. Paid fulfillment follows provider-confirmed payment/capture; licenses and protected download links are emailed after queueing succeeds.
- Subscription failures use a three-day grace period; lifecycle cron suspends access after grace/paid-through expiry. Refunds suspend licenses; disputes mark orders disputed and suspend licenses.
- Plugin version is now 0.3.1; database schema version is 7.

CURRENT OVERRIDE — 2026-10-15
Customer-facing account portal source was added in commit https://github.com/ruelporlas/dropkey-version2/commit/65af56a43bb0a82ff9791a44db0426a2043a4f24. GitHub Actions run https://github.com/ruelporlas/dropkey-version2/actions/runs/38655993037 passed PHP syntax checks and existing network-free contract tests on PHP 7.4, 8.0, and 8.3. WordPress runtime and browser verification remain NOT RUN.

- Shortcode `[dropkey_account]` displays account-linked licenses, copyable keys for newly issued licenses, activations and deactivation, subscription state, purchase history, fresh protected download links, and profile/password forms.
- Schema version is now 7. The licenses table adds `customer_user_id` and nullable `key_encrypted`. New keys remain SHA-256 hashed for validation and also receive AES-256-GCM encrypted storage for owner display.
- Signed-in checkout links an order only when the submitted email matches the logged-in WordPress user's email. New licenses inherit that user ID. Customer record queries and actions use user-ID ownership checks.
- Guest-purchase linking remains unimplemented; guest purchases are not auto-claimed by email. Existing keys issued before encrypted storage cannot be recovered from hashes. Encryption depends on stable WordPress auth salts.
- Subscription cancellation remains administrator-managed. Payment-method portal actions are not implemented.
- Next step: install on backed-up WordPress staging and test schema migration, account ownership, deactivation, download link generation, key display, profile/password behavior, and mobile layout.
