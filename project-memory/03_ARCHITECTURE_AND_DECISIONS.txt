DECISION LOG

Date: 2026-10-14
Decision: Use Product → Tier → Billing Options as the product-offering model.
Context / problem: The user wants multiple licensing tiers and needs the activation limit to be configurable per tier, while supporting free, one-time, monthly, and yearly offerings.
Options considered: (1) Each tier has billing options; (2) each tier-and-billing combination is treated as a separate plan.
Reason for choosing: The user asked to choose the simpler option and agreed to the recommendation. Keeping tier settings together avoids duplicating tier-level settings such as activation limits across billing variants.
Consequences and trade-offs:
- A product can have multiple tiers.
- A tier owns tier-level entitlements, including its configurable maximum active website count.
- Each tier can enable applicable billing options (free, one-time, monthly, yearly).
- Prices and billing cadence belong to their respective billing options.
- Tier names and activation counts are not fixed by this decision.
Status: accepted.
Evidence or related files: project-memory/04_REQUIREMENTS_AND_RULES.txt, DK-008 and DK-010.

Date: 2026-10-14
Decision: Admin-managed subscription cancellation takes effect at the end of the paid period.
Context / problem: The cancellation operator and effective timing needed an explicit policy.
Options considered: Immediate cancellation; end-of-paid-period cancellation; admin chooses either timing.
Reason for choosing: The user explicitly selected end-of-paid-period cancellation.
Consequences and trade-offs:
- Cancellation is initiated by an administrator, not by customer self-service in the initial workflow.
- The customer retains eligible paid access through the paid-through date.
- Status transitions, notices, and any admin override/exception flow still need specification.
Status: accepted.
Evidence or related files: User instruction on 2026-10-14; project-memory/04_REQUIREMENTS_AND_RULES.txt, DKD-006.

Decision: Implement the Milestone 1 WordPress foundation and core data model.
Context / problem: The user explicitly authorized coding Milestone 1 with GitHub as the first development target.
Implementation choices made within this milestone:
